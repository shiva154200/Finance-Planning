# Finance Planning

AI-powered personal finance planning platform that analyzes a customer's financial profile, generates personalized financial plans, and uses Gemini AI to explain the results in simple language.

The project combines a **React frontend**, **Node.js/Express backend**, **Python FastAPI planning service**, **MongoDB**, historical financial data, and **Gemini AI**.

> **Important:** Financial calculations and plan values are generated by the Python planning service. Gemini is used as an explanation layer and should not be treated as the calculation engine.

## Features

- User registration and login with JWT authentication
- Customer financial profile collection
- Customer financial analysis
- Risk-related analysis and profile information
- Savings rate, debt-to-income ratio, net worth, and goal-gap analysis
- Historical financial-data analysis
- Personalized asset allocation across Equity, Debt, Gold, and FD
- Balanced and Growth financial plans
- Expected return and volatility estimates
- Required monthly investment calculation
- Gemini-generated financial explanations and recommendations
- Dashboard with financial-plan visualizations

## Environment Variables

Create a `.env` file inside the `backend/` directory:

```env
PORT=5000
MONGO_URI=mongodb://127.0.0.1:27017/finance-planning
JWT_SECRET=your_jwt_secret_here
Gemini_API_Key=your_gemini_api_key_here
ML_SERVICE_URL=http://localhost:8000
```

| Variable | Purpose |
|---|---|
| `PORT` | Backend server port |
| `MONGO_URI` | MongoDB connection string |
| `JWT_SECRET` | Secret used to sign JWT tokens |
| `Gemini_API_Key` | Gemini API key |
| `ML_SERVICE_URL` | URL of the Python planning service |

**Never commit real API keys, JWT secrets, passwords, or other credentials to GitHub.**

## Running the Project Locally

The application uses three services. Run each service in a separate terminal.

### 1. Start MongoDB

Start your local MongoDB service, or use a MongoDB Atlas connection string in `MONGO_URI`.

### 2. Start the Python Planning Service

Open Terminal 1:

```bash

python -m venv venv
```

#### Windows PowerShell

```powershell

```


Start FastAPI:


The service runs at:


```text

```

Expected response:

```json

  "status": "healthy"

```

Open Terminal 2:


Open Terminal 3:

Open the Vite URL shown in the terminal, normally:

## Financial Planning Engine

### Customer Analysis

The planning service processes the customer's financial profile and derives metrics such as:

- Monthly savings
- Savings rate
- Debt-to-income ratio
- Total assets
- Total liabilities
- Net worth
- Goal gap
- Risk-related information

### Risk Analysis

The planning pipeline uses the customer's risk-related information together with their financial profile when generating the plans.

The planning result can contain information such as:

- Risk tolerance
- Investment experience
- Risk score
- Risk profile
- Financial goal
- Time horizon

### Historical Analysis

Historical financial data is used to analyze factors such as:

- Asset returns
- Asset volatility
- Correlations
- Market trends
- Economic conditions

The project contains datasets under `ml-service/datasets/` for the current development/training workflow.

### Portfolio Allocation

The planning service generates allocations across:

- Equity
- Debt
- Gold
- FD

The allocation is influenced by the customer's financial profile, risk-related information, goal, and time horizon.

### Plan Generation

The application generates alternative financial plans, including:

| Plan | Purpose |
|---|---|
| **Balanced Plan** | A more balanced allocation suitable for the customer's calculated profile |
| **Growth Plan** | A more growth-oriented alternative with relatively greater exposure to Equity |

Plans can include:

- Asset allocation
- Expected annual return
- Expected volatility
- Required monthly investment
- Risk information
- Financial goal
- Time horizon

### Gemini Explanation Layer

The backend sends planning results to Gemini to generate human-readable explanations such as:

- Executive summary
- Plan comparison
- Pros and cons
- Actionable steps
- Recommendation

Gemini is an explanation layer and should not be considered the source of the numerical planning calculations.

## API Endpoints

### Backend API

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/auth/register` | Register a new user |
| `POST` | `/api/auth/login` | Login and receive JWT |
| `GET` | `/api/auth/me` | Get authenticated user |
| `POST` | `/api/profile` | Save customer financial profile |
| `POST` | `/api/plans` | Generate a financial plan |

Protected endpoints require a valid JWT token.

### Python Planning Service

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/` | Service status |
| `GET` | `/health` | Health check |
| `POST` | `/generate-plan` | Generate plans from customer financial data |

The `/generate-plan` endpoint accepts the customer profile defined by the FastAPI request model and returns the planning-engine result.

## Troubleshooting

### Frontend cannot connect to backend

Make sure the backend is running on port `5000` and that the frontend API configuration points to the backend.

### Backend cannot connect to the Python service

Make sure the Python service is running on port `8000` and that the backend `.env` contains:

```env
ML_SERVICE_URL=http://localhost:8000
```

### MongoDB connection error

Check that MongoDB is running and that `MONGO_URI` is correct.

For local MongoDB:

```env
MONGO_URI=mongodb://127.0.0.1:27017/finance-planning
```

### Gemini errors

Check that:

- `Gemini_API_Key` is present in `backend/.env`
- The API key is valid
- The Gemini API is available for your account/project

### Python dependency errors

Create and activate the virtual environment and install the required packages:

```bash
cd ml-service
python -m venv venv
pip install -r requirements.txt
```
